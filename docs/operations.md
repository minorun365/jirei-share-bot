# 運用

## スレッドでの会話

Botへのメンションに加えて、パブリックチャンネルのスレッド返信（メンションなし）も受け付けます。メンションなしの返信に答えるのは、直前の発言がBotのときだけです。次の返信には答えません。

- Botへのメンションを含む返信（`app_mention` 側で処理するため）
- ほかの人へのメンションを含む返信（人同士の会話に割り込まないため）
- 直前の発言が人の返信
- 親投稿、Botの投稿、編集・削除などの `subtype` 付きイベント

判定のためにスレッドの発言を読むのは、受付後の非同期処理の中だけです。それ以外の投稿は受付時点で捨て、保存しません。Slack Appには `message.channels` イベントの購読が必要です。追加のスコープは要りません（`channels:history` で足ります）。

同じスレッドでBotがすでに名指しした事例については、詳細回答で事例名の前置きを繰り返しません。同じ事例のグラレコ画像がスレッドに貼られていれば、利用者が画像そのものを求めたときを除いて貼り直しません。

## 日次共有のスキップ

日次共有は、日本の祝日と年末年始に投稿しません。EventBridge Schedulerのcron式は曜日しか指定できないため、Lambdaが実行時に日本時間の日付で判定します。

| 対象 | 内容 |
|---|---|
| 国民の祝日 | 祝日法の規則から計算します。春分の日・秋分の日は近似式で求めます |
| 振替休日 | 祝日が日曜のとき、その後の最初の祝日でない日 |
| 国民の休日 | 前日と翌日が祝日に挟まれた平日 |
| 年末年始 | 12月29日〜1月3日 |

判定の対象は2026年〜2099年です。即位礼の日のように法律で個別に定まる臨時の祝日は規則から導けないため、[src/domain/jp-holidays.ts](../src/domain/jp-holidays.ts) の `EXTRA_HOLIDAYS` に `YYYY-MM-DD` 形式で追加してください。年末年始の期間も同じファイルで変更できます。

`dailyShareTimezone` を日本時間以外にしても、スキップの判定は日本時間の日付で行います。

## 失敗の通知

`cdk.json` の `ownerSlackUserId` に開発者のSlackユーザーIDを設定すると、Bot側の失敗をSlackで開発者へ知らせます。空欄なら通知しません（失敗はCloudWatch Logsにだけ残ります）。

| 失敗 | 通知先 |
|---|---|
| 依頼の処理中の失敗（Runtimeが `owner_alert` を返した、応答を読めなかった、処理中に例外が出た） | 失敗したスレッドへの返信の末尾で、開発者へメンション |
| 日次共有の失敗 | 定期共有先のチャンネル（`targetChannelId`）で、開発者へメンション |
| 処理待ちキューのアラーム（デッドレターキューにメッセージがある、最古のメッセージが15分以上滞留） | 定期共有先のチャンネルで、開発者へメンション |

キューのアラームは、CloudWatchアラーム → SNSトピック → Slackイベントを処理するLambda の順に届きます。メンションには失敗の種類を表す短い識別子が付きます。

## 定期処理の停止

`cdk.json` の `schedulesEnabled` を `"false"` にするか、`-c schedulesEnabled=false` を付けてデプロイすると、日次共有・ナレッジベース同期・グラレコ生成の定期処理をすべて無効の状態で作ります。新しい環境を作って切り替える前の準備や、一時停止に使います。

```sh
npx cdk deploy --all -c schedulesEnabled=false
```

再開するときは `schedulesEnabled` を `"true"` に戻してデプロイします。
