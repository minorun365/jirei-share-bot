# 事例の登録・追記と版履歴

事例共有くんは、Slackの依頼を「何を頼んでいるか」で判定してから、事例の登録・追記・取り消しを行います。既存の事例を書き換える操作は、対象を取り違えるとその事例の情報が失われるため、判定と書き込みの間に関門を置いています。

## 意図判定

Botへのメンションを受けると、エージェントがツールを選ぶ前に、受付のモデルが依頼の意図を1つ判定します。判定結果は意図と確信度（0〜1）です。

| 意図 | 内容 | 主に使うツール |
|---|---|---|
| `register` | 新しい事例として登録してほしい | `register_case_tool` |
| `append` | 既存の事例に追記・修正してほしい | `update_case_tool` / `confirm_pending_update_tool` |
| `revert` | 直前の更新を取り消して前の内容に戻してほしい | `revert_case_tool` |
| `search` | 事例を探したい | `retrieve_cases_tool` → `search_cases_tool` |
| `detail` | 直前に出た事例の中身を知りたい | `get_case_context_tool` → `describe_case_tool` |
| `next_action` | 事例を見つけた後、誰に聞くか・どう進めるか | `case_next_action_tool` |
| `graphic` | 事例のグラレコ画像を見たい | `get_case_graphic_tool` |
| `bot_question` | Bot自身（モデル、作り方、データの扱い）についての質問 | `describe_bot_tool` |
| `chat` | お礼・相づち・Botの直前の動作への質問 | `chat_reply_tool` |
| `out_of_scope` | 事例共有と無関係な依頼 | `unsupported_request_tool` |

書き込み系のツール（登録・追記・取り消し）は、判定された意図が自分の種類と一致し、確信度が0.7以上のときだけ書き込みます。食い違う・確信度が低いときは書き込まずに、新規登録か追記かを利用者へ聞き返します。依頼文に「Bot」「Claude」などの語が含まれていても、登録・追記を頼んでいれば登録・追記として扱います。

利用者が「別件」「新規で」「別の事例として」と明言した登録は、似た既存事例があっても聞き返さずに登録します。

## 追記先の選び方

追記先の事例は、エージェントが会話から選んで `case_id` でツールへ渡します。材料は、スレッドの発言、スレッドに紐づく事例、聞き返しで示した候補、ナレッジベースの検索結果です。コードは点数付けや引用符の正規表現で追記先を決めません。

- スレッドに紐づく事例があり、利用者が別の事例を指していなければ、その事例が既定の追記先です。
- 追記先を1件に決めきれないときは、追記したい内容をスレッドに預け、候補を番号付きで示して聞き返します。利用者は「2番に追記して」のような番号でも、事例名でも答えられます。
- 会話から追記先の見当がついたときは、その1件に絞って預け直し、「お願い」と返せば追記できる案内を返します。
- 預かった内容は24時間で使わなくなります。話題が変わっている前提で、古い預かりへは書き込みません。

## 追記の反映

追記は既存の内容を置き換えません。紹介文・課題・取り組み・効果はモデルが前の版と今回の内容を統合し、技術・タグは和集合にします。統合結果が前の版より極端に短い場合は、事実を落としたとみなして機械的な連結に切り替えます。

事例のタイトルは追記では変えません。「タイトルを〇〇に変えて」のように改名を明示されたときだけ変えます。

次の場合は、書き込まずに利用者へ確認します。

- 追記内容の顧客名が、更新対象の事例と別の組織を指している（「〇〇じゃなくて△△が正しい」のような顧客名の訂正依頼は通します）
- 同じ依頼の中で、すでに別の事例を更新している（1回の依頼で更新する既存事例は1件だけです）

日次共有では、顧客名がタイトルと食い違い、ほかの事例の組織名と一致するカードを、別案件が混ざった疑いがあるとして共有対象から外します。「社内（情報システム）」のような社内ラベルや部署名だけの顧客名は対象外です。

## 版履歴

事例を書き換えるたびに、DynamoDBの版履歴テーブル（`CaseRevisionsTable`）へ1版を追加します。キーは `case_id` と `revision`（数値）です。

| 種類 | 版番号 | 内容 |
|---|---|---|
| `register` | 1 | 登録した内容 |
| `baseline` | 0 | 版履歴が無い既存事例を初めて更新するときの、更新前の内容 |
| `update` | 前の版＋1 | 追記・修正後の内容 |
| `revert` | 前の版＋1 | 前の版へ戻した内容 |

版履歴の書き込みに失敗した場合は、事例本体を書き換えません。事例本体は `revision` を条件にした条件付き書き込みで更新し、同じ事例が別の依頼で先に更新されていたら反映しません。

## 元に戻す

「元に戻して」「さっきの更新を取り消して」と頼むと、スレッドに紐づく事例（または指定した事例）を1つ前の版の内容へ戻します。戻す操作も新しい版として積むので、戻す前の内容も履歴に残ります。グラレコ画像の状態や最終共有日時は、戻した後も今の値を引き継ぎます。

## 意図判定の評価

[eval/eval_intents.py](../eval/eval_intents.py) は、[eval/intent-cases.json](../eval/intent-cases.json) の会話例を本物のモデルで流し、選ばれたツールと書き込んだ事例を採点します。事例テーブル・版履歴・スレッド状態・ナレッジベースはメモリ上の偽物に差し替え、架空の事例（`seed_cases`）で動かすので、AWS上のデータには触れません。必要なのは利用するBedrockモデルへのアクセスだけです。

```sh
AWS_REGION=ap-northeast-1 BEDROCK_MODEL_ID=<モデルIDまたは推論プロファイルID> \
uv run --with-requirements agentcore-runtime/requirements.txt \
  python eval/eval_intents.py --min-accuracy 0.95
```

合格率が `--min-accuracy` を下回るか、意図判定が1件でも失敗すると非0で終了します。プロンプトやモデルを変える前後で比べてください。

[eval/canary_revisions.py](../eval/canary_revisions.py) は、デプロイ済みの事例テーブルと版履歴テーブルに架空の `E2E_TEST_` 事例を作り、登録 → 追記 → 元に戻す を通してから削除します。

```sh
AWS_REGION=ap-northeast-1 BEDROCK_MODEL_ID=<モデルIDまたは推論プロファイルID> \
CASES_TABLE_NAME=<事例テーブル名> CASE_REVISIONS_TABLE_NAME=<版履歴テーブル名> \
uv run --with-requirements agentcore-runtime/requirements.txt python eval/canary_revisions.py
```
