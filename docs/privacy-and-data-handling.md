# データの取り扱い

このBotは社内の取り組み事例を保存し、Slackへ再投稿します。導入する組織は、保存してよい情報と投稿してよい情報を事前に決めてください。

## 保存しない情報

- APIキー、パスワード、トークン、Cookie
- 個人のメールアドレス、電話番号、住所
- 顧客担当者など、外部の個人を特定できる情報
- アクセス権を限定したログ、データベースの内容、未公開のセキュリティ情報
- 組織の規定でBotへの入力を認めていない情報

## コードが行う検査

投稿前に、メールアドレス、電話番号、Slack Token、AWSアクセスキー、APIキーらしい文字列などを検査します。検出した内容に応じて、伏せ字にするか処理を停止します。

正規表現とAIモデルによる検査には見落としがあり、Botが自動で安全性を保証できるわけではありません。Slack Appを追加するチャンネル、AWSへの保存期間、CloudWatch Logsの閲覧権限も組織側で管理してください。

## Slackの権限

初期構成では、パブリックチャンネルの `app_mention` とスレッド返信の `message.channels` イベントを受け取ります。`message.channels` は、Botの回答直後にメンションなしでついたスレッド返信へ応答するためだけに使い、それ以外の投稿は受け取った時点で破棄して保存しません。`channels:history` は、Botがメンションされた同じスレッドの文脈を読み取るときと、メンションなしの返信がBotの回答への返事かを確認するときに使います。全チャンネルの常時収集、DM、プライベートチャンネルは対象外です。

事例の版履歴には、書き換え前後の内容、依頼した利用者のSlackユーザーID、依頼のスレッド時刻を保存します。版履歴は削除しない設計のため、消す必要がある場合は版履歴テーブルから該当事例の版を直接削除してください。

画像生成を有効にする場合だけ `files:write` を追加し、使わない機能の権限は追加しないでください。

## テストとIssue

テストデータ、バグ報告、スクリーンショットには架空の組織名と人名を使ってください。本番のSlack本文、チャンネルID、スレッド時刻、AWSリソースIDを公開Issueへ貼らないでください。
