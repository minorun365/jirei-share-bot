# データの取り扱い

このBotは社内の取り組み事例を保存し、Slackへ再投稿します。導入する組織は、保存できる情報と投稿できる情報を事前に決めてください。

## 保存しない情報

- APIキー、パスワード、トークン、Cookie
- 個人のメールアドレス、電話番号、住所
- 顧客担当者など、外部の個人を特定できる情報
- アクセス権を限定したログ、データベースの内容、未公開のセキュリティ情報
- 組織の規定でBotへの入力を認めていない情報

## コードが行う検査

投稿前に、メールアドレス、電話番号、Slack Token、AWSアクセスキー、APIキーらしい文字列などを検査します。検出内容に応じて伏せ字化または処理停止を行います。

正規表現とAIモデルによる検査には見落としがあります。Botが自動で安全性を保証するものではありません。Slack Appを追加するチャンネル、AWSへの保存期間、CloudWatch Logsの閲覧権限も組織側で管理してください。

## Slackの権限

初期構成ではパブリックチャンネルの `app_mention` だけを受け取ります。Botがメンションされた同一スレッドの文脈を読むために `channels:history` を使います。全チャンネルの常時収集、DM、プライベートチャンネルは対象外です。

画像生成を有効にする場合だけ `files:write` を追加します。使わない機能の権限は追加しないでください。

## テストとIssue

テストデータ、バグ報告、スクリーンショットには架空の組織名と人名を使ってください。本番のSlack本文、チャンネルID、スレッド時刻、AWSリソースIDを公開Issueへ貼らないでください。
